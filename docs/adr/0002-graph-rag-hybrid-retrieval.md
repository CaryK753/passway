# ADR-0002：采用 Graph RAG 主导的混合检索

## 状态

Superseded by ADR-0004

## 日期

2026-09-08

> 本文保留为早期决策记录。当前由 WeKnora 承担检索、Auto-Wiki 与派生图谱，详见 [ADR-0004](0004-github-content-and-weknora-derived-knowledge.md)。

## 背景

移民问题通常跨越申请人条件、法域、签证路径、临时身份、永居、入籍、家属权利和官方规则。纯向量检索擅长语义近似，但不能稳定表达法域边界、前置条件、身份演进和规则时效。

## 决策驱动因素

- 检索必须尊重国家、地区、时间和申请人身份。
- 回答需要发现多跳路径，而不只是相似段落。
- 用户问题仍可能使用与文档不同的自然语言。
- 每个结论必须提供可验证的文件与来源链。
- 首版运维复杂度需要保持在 PostgreSQL 和应用层可承受范围内。

## 考虑的方案

### 方案 A：纯向量 RAG

实现简单，但容易混淆相似法域和过期规则，多跳能力弱。

### 方案 B：专用图数据库上的纯图检索

关系表达强，但自然语言召回较弱，且过早引入额外基础设施。

### 方案 C：Graph RAG 主导的混合检索

先用结构化条件确定图入口和边界，再结合全文与向量寻找候选节点，执行受约束的图扩展和重排。

## 决策

选择方案 C。图关系是主要组织和推理结构；metadata 过滤、全文检索和向量相似度是入口发现及召回补充。首版使用 PostgreSQL 节点表与边表投影，不引入专用图数据库。

## 后果

### 正面

- 能表达路径之间的前置、替代、转化和排除关系。
- 可将语义召回限制在正确的法域和时间范围内。
- 引用链天然对应 Vault 文件和来源节点。
- 后续可替换 embedding 或重排模型而不改变内容事实源。

### 负面

- 内容作者需要维护显式关系。
- 索引器和检索器比简单向量 RAG 更复杂。
- 必须建设图召回评测，不能只看语义相似度。

### 风险与缓解

- 图谱稀疏导致漏召回：用全文和向量补充候选，并报告缺失关系。
- 图扩展过宽导致噪声：按边类型、法域、有效期和最大跳数限制扩展。
- LLM 擅自补边：运行时只允许使用索引中存在的边，推断关系必须明确标记，不能写回事实图。
