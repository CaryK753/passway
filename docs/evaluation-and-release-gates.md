# 评测与发布门槛

## 1. 原则

Passway 的质量不能以“页面能打开”或“回答看起来合理”衡量。评测必须覆盖内容正确性、图关系、检索证据、回答忠实度、隐私、安全、成本和故障降级。

所有评测记录：内容快照、代码版本、模型与参数、测试集版本和运行日期。更换模型或检索策略后必须重新运行相关门槛。

## 2. 测试集设计

测试问题按以下维度分层：

| 类型 | 目的 |
| --- | --- |
| 单文章事实 | 验证正确文章和来源召回 |
| 跨文章路径 | 验证要求、身份和后续路径覆盖 |
| 路径比较 | 验证可比字段和差异解释 |
| 法域陷阱 | 验证相似制度不会跨国家污染 |
| 时间旅行 | 验证历史日期与当前规则隔离 |
| 信息不足 | 验证追问和 `unknown` |
| 明确不满足 | 验证规则判断与替代路径 |
| 来源冲突 | 验证不确定性展示和拒绝武断结论 |
| 提示注入 | 验证来源文本和用户输入不能覆盖系统边界 |
| 故障降级 | 验证模型、向量或数据库不可用时仍安全 |

每个问题保存期望文章、必要事实、允许的结论、禁止的结论和最低来源集合。

## 3. 内容门槛

MVP 发布必须满足：

- 发布文章 100% 通过 schema；
- 断链、重复 `content_id` 和未解释时间冲突均为 0；
- 已核验硬性结论的合格官方来源覆盖率为 100%；
- 所有发布文章都有法域、有效期语义、复核日期和复核状态；
- `stale`、`conflicted` 和 `draft` 不进入确定性 AI 证据集；
- 至少一次完整内容更新演练和一次紧急撤回演练通过。

## 4. 检索门槛

在固定测试集上，首发目标为：

| 指标 | 门槛 |
| --- | --- |
| 必要文章 Recall@context | ≥ 0.95 |
| 必要来源覆盖率 | ≥ 0.98 |
| 必要事实覆盖率 | ≥ 0.90 |
| 法域污染率 | 0 |
| 时间污染率 | 0 |
| 未核验内容进入确定性证据集 | 0 |

上述数值是首版产品安全门槛，不是模型排行榜。若测试集过小或过于简单，即使达标也不能发布；测试集必须包含失败诱导和边界案例。

## 5. 回答门槛

采用自动检查与人工盲评结合：

- 关键事实引用覆盖率 ≥ 0.98；
- 引用支持对应陈述的精确率 ≥ 0.98；
- unsupported claim rate = 0；
- 明确编造的路径、门槛、机关或来源 = 0；
- 将 `unknown` 改写成肯定/否定 = 0；
- 将替代关系描述为自动转换关系 = 0；
- 对缺失关键条件的测试，正确追问或保留不确定性 ≥ 0.95；
- 每个路径建议都展示信息日期、适用法域和非法律意见边界。

任何严重错误案例优先级高于总体平均分。涉及错误法域、过期门槛或虚构资格的单个可复现问题，都必须阻止发布。

## 6. 性能与可用性门槛

初始目标在 Phase 3/4 用真实部署修订：

- Wiki 页面不依赖 AI 服务即可生成和访问；
- 搜索、Wiki 与图谱失败时返回明确错误，不展示旧派生版本为最新；
- AI 首个可见响应应支持流式输出；
- 请求超时、模型限流和预算耗尽均有用户可理解的降级；
- 生产快照可回滚，恢复演练不依赖作者本机 iCloud 目录。

不在缺乏真实负载前承诺具体延迟百分位。

## 7. 隐私与安全门槛

- 默认不持久化用户 profile 或完整对话；
- 日志、分析和错误追踪不包含原始敏感背景；
- Git 内容、manifest 和响应不包含本地绝对路径或密钥；
- 用户输入和抓取来源不能指示系统泄露提示词、读取私有文件或改变发布状态；
- 匿名接口具备 IP/设备维度公平使用限制和全局预算熔断；
- 管理密钥仅存在服务端，浏览器只获得最小匿名权限；
- 数据库 RLS、公开 bucket 和 API 权限在上线前单独审核。

## 8. 成本门槛

Phase 5 前先确定：

- 每日和每月硬预算；
- 单次请求最大检索量、输入 token 和输出 token；
- 缓存只能复用不含个人 profile 的公共查询结果；
- 达到 80% 预算时告警，达到硬上限时自动关闭生成式回答；
- AI 关闭后自动引导到 Wiki 搜索和相关页面。

若无法建立硬预算熔断，不开放免登录 AI。

## 9. 发布检查清单

- [ ] Phase 0 至 Phase 5 的 Exit Gate 均有证据。
- [ ] 当前内容快照和应用版本已冻结。
- [ ] 内容、检索、回答、安全和成本评测全部通过。
- [ ] 备份、恢复、回滚和紧急撤回演练通过。
- [ ] 公开展示来源、核验时间、免责声明和纠错入口。
- [ ] 监控能区分应用故障、内容过期、检索回归和模型故障。
- [ ] 上一有效版本可以在新版本失败时恢复。

## 10. 停止条件

出现以下任一情况时暂停扩大覆盖或暂停匿名 AI：

- 已发布内容出现系统性无来源、错误时间或错误法域问题；
- 内容更新速度低于政策变化速度，且无法及时标记过期；
- 检索或回答在严重案例上出现重复回归；
- 无法证明用户敏感背景未被持久化；
- 成本熔断失效或匿名滥用影响 Wiki 可用性；
- 发布版本不可回滚或无法从 Git commit 重建 WeKnora 知识。
