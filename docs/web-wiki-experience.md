# Passway Web 阅读、Wiki、图谱与问答体验

## 1. 产品边界

Web 聚合四类体验：

- GitHub 中的人工 Markdown 文章；
- WeKnora 生成的 Auto-Wiki；
- Wiki 页面链接图，以及后续可选的实体关系图；
- WeKnora 驱动的带引用问答。

Web 不是 CMS。文章编辑和复核通过本地 Git 工作流完成；生成内容不写回文章。

## 2. 信息架构

```text
左侧：文章/Wiki 导航与搜索
中部：标签页和活动页面
右侧：元数据、来源、反向链接、问答引用
底部或停靠面板：关系图谱
```

小屏幕优先单页面，导航、上下文和图谱进入抽屉。

## 3. 内容类型

### 人工文章

显示核验状态、适用法域、有效时间、官方来源和纠错入口。它是默认阅读入口，也是 AI 引用的主要落点。

### AI Wiki

必须显示“由 WeKnora 根据指定内容版本生成”、生成时间和对应 source commit。允许页面导航、索引、反向链接和修订查看，但不得使用与人工核验文章相同的可信状态样式。

### 图谱

默认显示 Wiki 页面链接图，并明确说明边表示页面链接。实体关系图使用独立视图和图例，只有质量与性能通过评测后才开放。

### 问答

MVP 可使用 WeKnora Embed；正式版通过服务端 Chat API 自建界面。回答引用可打开到人工文章、原始来源或 Wiki 页面，并明确区分三者。

## 4. 阅读与工作区

- 支持 `system/light/dark` 主题和统一语义色。
- 普通点击在当前标签打开；可在新标签或相邻分屏打开。
- 首版只要求一主一副双栏，不实现任意网格。
- 人工文章与 Wiki 页面可以并排对照。
- URL 可深链到文章或 Wiki 页面；本地工作区状态不成为分享链接的必要条件。
- AI、Wiki 或图谱不可用时，文章阅读仍完整工作。

## 5. 图谱交互

- 从当前页面加载邻居，不默认绘制全库。
- 支持搜索、类型筛选、逐步展开和节点上限。
- 点击节点显示标题、类型、生成状态和关联文章。
- 从图谱打开页面时可选择当前标签、新标签或分屏。
- 页面链接图和实体关系图不得混合为无类型边。
- 超过阈值时截断并解释，不制造不可读的毛线团。

## 6. 安全与缓存

- 浏览器不接触 WeKnora 管理 API Key。
- Markdown 禁止脚本和不受控 HTML。
- WeKnora 数据通过服务端 Adapter 归一化、校验和缓存。
- 人工文章版本与 Wiki 版本不一致时显示同步延迟，不拼成一个看似一致的页面。
- 资源引用采用受控代理或短期 URL，日志不记录匿名可读链接。
- 草稿和内部评审信息不进入公开页面或生产知识库。

## 7. MVP 验收

- 任一人工文章可在无 WeKnora 情况下打开。
- Wiki 索引和页面可追溯到已知生成版本。
- 页面链接图可从当前页渐进浏览。
- 用户能清楚区分人工文章、AI Wiki 和两种图谱。
- 问答引用能打开对应内容，引用失效时明确降级。
- 主题、标签页、分屏和移动端不改变内容语义。
